# Bean

En Spring, el contenedor Bean (conocido formalmente como el contenedor de Inversión de Control o IoC Container) es el "corazón" de Spring Framework y Spring Boot.

## Para entenderlo de forma sencilla:

### ¿Qué es un Bean? En Spring.
- Un Bean es un objeto Java cuya creación, configuración y ciclo de vida son administrados por el contenedor de Spring.

- ```Ojo, @Service, @Repository, etc, no son Bean son anotaciones.```
##### Ejemplo
```java
@Service
public class TransferService {

    private final AccountRepository repository;

    public TransferService(AccountRepository repository) {
        this.repository = repository;
    }
}
```
### Esto es un Bean
```
@Service                 → Anotación
TransferService          → Clase
new TransferService(...) → Objeto / instancia
                           administrada por Spring
                           = Bean
```

### ¿Qué es el contenedor? 
- Es un gran administrador (una especie de fábrica o memoria central) que se encarga de crear los objetos por ti (instanciarlos).

    - Inyectar automáticamente las dependencias que necesitan (por ejemplo, pasarle tu JdbcTemplate al repositorio sin que tengas que hacer un new JdbcTemplate() a mano).

    - Gestionar su ciclo de vida (sabe cuándo crearlos, usarlos y destruirlos cuando la aplicación se apaga).

- Es decir:
```
Objeto Java NO administrado por Spring
→ normalmente tú lo creas con new
→ tú proporcionas/administra sus dependencias
→ tú controlas su ciclo de vida

Bean de Spring
→ también es un objeto Java
→ pero está administrado por el Spring Container
→ Spring controla su creación
→ Spring resuelve/inyecta sus dependencias
→ Spring administra su ciclo de vida
```
## Entonces, ¿quién crea el objeto?

### El Spring Container.

```
                SPRING CONTAINER
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
   Creación        Inyección       Ciclo de vida
   de Beans       dependencias      de Beans
```

## ¿Por qué es importante?
- En Java tradicional, si una clase necesita a otra, tú mismo tienes que instanciarla con la palabra clave new.
- En Spring, gracias al contenedor Bean, tú solo le dices a Spring qué clases administrar (usando anotaciones como @Repository, @Service, @Component o @Bean) y el contenedor se encarga de guardarlas y dárselas a otras clases cuando las soliciten (Inyección de Dependencias).

### ¿Qué problema resuelve?
 - Creacion con la palabra clave new 
 - ```TransferenciaService``` está fuertemente acoplado a ``CuentaRepository``, porque crea directamente su dependencia.
 ```java
public class TransferenciaService {

    private final CuentaRepository cuentaRepository;

    public TransferenciaService() {
        this.cuentaRepository = new CuentaRepository();
    }
}
 ```
- Con Spring, ambos objetos pueden ser Beans:
```java
@Repository
public class CuentaRepository {
}

@Service
public class TransferenciaService {

    private final CuentaRepository cuentaRepository;

    public TransferenciaService(CuentaRepository cuentaRepository) {
        this.cuentaRepository = cuentaRepository;
    }
}
```
- Spring se encarga de:
    
    1. Crear CuentaRepository.
    2. Crear TransferenciaService.
    3. Entregarle el Bean CuentaRepository mediante el constructor.
    4. Mantener ambos objetos disponibles dentro del contenedor.

- ### Conceptualmente ocurre
```
Spring inicia
    ↓
Escanea las clases
    ↓
Encuentra @Repository
    ↓
Registra AccountRepository como Bean
    ↓
Encuentra @Service
    ↓
Registra TransferService como Bean
    ↓
Detecta que TransferService necesita AccountRepository
    ↓
Crea/resuelve AccountRepository
    ↓
Crea TransferService(repository)
    ↓
Administra ambos Beans
```

## ¿Dónde viven los Beans?
- Los Beans se registran dentro del Spring Container, representado normalmente por un ``ApplicationContext``.
```
ApplicationContext
├── cuentaRepository
├── transferenciaService
├── transferenciaController
└── notificacionService
```
- Cuando inicia la aplicación, Spring construye este contexto y registra las definiciones de los Beans.

##  Mediante @Bean
- Se utiliza cuando queremos crear y configurar el objeto explícitamente.
```java
@Configuration
public class BancoConfig {

    @Bean
    public CalculadoraComision calculadoraComision() {
        return new CalculadoraComision(0.015);
    }
}
```
- Spring ejecuta ese método y registra el objeto retornado como Bean.

- Esta alternativa es especialmente útil cuando:

    - La clase pertenece a una librería externa.
    - Necesitamos personalizar su construcción.
    - No podemos colocarle @Component.
    - Queremos controlar explícitamente su configuración.


### Confusiones frecuentes
- Bean no es una clase: es el objeto administrado por Spring.
- No todo objeto Java es un Bean: debe registrarse en el contenedor.
- @Bean y Bean no son lo mismo: Bean es el objeto; @Bean es una forma de registrarlo.
- @Service no realiza por sí solo la inyección: registra la clase como Bean; el contenedor resuelve e inyecta sus dependencias.
- Singleton de Spring no significa una instancia para toda la JVM: significa una instancia dentro de un ApplicationContext.
### 1. Anotaciones que crean o registran Spring Beans

| Anotación | ¿Es Spring Bean? | ¿Se puede inyectar? | ¿Para qué sirve? | Ejemplo de uso |
|---|:---:|:---:|---|---|
| `@Component` | ✅ Sí | ✅ Sí | Declara una clase como componente genérico administrado por Spring. | Un componente para enviar correos, generar archivos o realizar una tarea reutilizable. |
| `@Service` | ✅ Sí | ✅ Sí | Declara una clase que contiene lógica de negocio. | Un `UsuarioService` que registra usuarios, valida datos o consulta información de negocio. |
| `@Repository` | ✅ Sí | ✅ Sí | Declara una clase destinada al acceso a datos. | Un `UsuarioRepository` que consulta, guarda, actualiza o elimina usuarios en la base de datos. |
| `@Controller` | ✅ Sí | ✅ Sí | Declara una clase como controlador MVC. | Un controlador que recibe una petición HTTP y devuelve una vista HTML. |
| `@RestController` | ✅ Sí | ✅ Sí | Declara un controlador para APIs REST. | Un `UsuarioController` que expone endpoints como consultar, crear o eliminar usuarios y devuelve JSON. |
| `@Configuration` | ✅ Sí | ✅ Sí | Declara una clase de configuración administrada por Spring. | Una clase donde se configura un cliente HTTP, un servicio externo o Beans personalizados. |
| `@Bean` | ✅ Sí | ✅ Sí | Registra explícitamente un objeto en el contenedor de Spring. | Registrar un cliente de conexión, un `ObjectMapper` personalizado o una instancia de una librería externa. |
| `@ControllerAdvice` | ✅ Sí | ✅ Sí | Define comportamiento global para los controladores. | Centralizar el manejo de excepciones de todos los controladores de la aplicación. |
| `@RestControllerAdvice` | ✅ Sí | ✅ Sí | Define comportamiento global para APIs REST. | Devolver respuestas JSON estandarizadas cuando ocurre una excepción en cualquier endpoint. |


### 2. Anotaciones que NO crean Spring Beans


| Anotación | ¿Es Spring Bean? | ¿Para qué sirve? | Ejemplo de uso |
|---|:---:|---|---|
| `@Autowired` | ❌ No | Indica que Spring debe inyectar una dependencia. | Solicitar que Spring proporcione un `UsuarioService` dentro de otra clase. |
| `@Qualifier` | ❌ No | Permite seleccionar específicamente qué Bean debe inyectarse cuando existen varios del mismo tipo. | Elegir entre `EmailService` y `SmsService` cuando ambos implementan `NotificationService`. |
| `@Primary` | ❌ No | Define qué Bean debe tener prioridad cuando existen varios del mismo tipo. | Marcar `EmailNotificationService` como implementación predeterminada de `NotificationService`. |
| `@Value` | ❌ No | Inyecta valores provenientes de la configuración de la aplicación. | Obtener la URL de una API externa definida en `application.properties`. |
| `@ComponentScan` | ❌ No | Indica dónde Spring debe buscar componentes para registrarlos como Beans. | Indicar que Spring debe buscar componentes dentro de un paquete específico. |
| `@Transactional` | ❌ No | Define un límite transaccional para una operación. | Hacer que el registro de un pedido y la actualización del stock se ejecuten dentro de una misma transacción. |
| `@Entity` | ❌ No | Define una entidad administrada por JPA/Hibernate. | Representar la tabla `usuarios` mediante una clase `Usuario`. |
| `@Table` | ❌ No | Configura la tabla asociada a una entidad JPA. | Indicar que la entidad `Usuario` corresponde a la tabla `usuarios`. |
| `@Id` | ❌ No | Define la clave primaria de una entidad JPA. | Indicar que `id` es el identificador único de un usuario. |
| `@Column` | ❌ No | Configura la relación entre un atributo y una columna de la base de datos. | Indicar que el atributo `correo` corresponde a la columna `email`. |
| `@OneToMany` | ❌ No | Define una relación uno-a-muchos entre entidades. | Un usuario puede tener muchas direcciones. |
| `@ManyToOne` | ❌ No | Define una relación muchos-a-uno entre entidades. | Muchos pedidos pueden pertenecer a un mismo usuario. |
| `@ManyToMany` | ❌ No | Define una relación muchos-a-muchos entre entidades. | Un usuario puede tener varios roles y un rol puede pertenecer a varios usuarios. |


### 3. Anotaciones que modifican el comportamiento de Spring Beans

| Anotación | ¿Crea Bean? | ¿Para qué sirve? | Ejemplo de uso |
|---|:---:|---|---|
| `@Scope` | ❌ No | Define el alcance y ciclo de vida de un Bean. | Crear un Bean nuevo cada vez que sea solicitado mediante el alcance `prototype`. |
| `@Lazy` | ❌ No | Retrasa la creación de un Bean hasta que realmente sea necesario. | Evitar inicializar un servicio pesado hasta que alguna parte de la aplicación lo utilice. |
| `@DependsOn` | ❌ No | Indica que determinados Beans deben inicializarse antes que otro. | Hacer que un Bean de configuración se inicialice después de que otro Bean requerido esté disponible. |
| `@Primary` | ❌ No | Establece un Bean como candidato principal cuando existen varios del mismo tipo. | Elegir automáticamente una implementación de `NotificationService` cuando existen varias. |
| `@Qualifier` | ❌ No | Permite seleccionar específicamente qué Bean utilizar. | Elegir explícitamente el servicio de notificaciones por correo en lugar del servicio SMS. |
